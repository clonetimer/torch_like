## Automated in-repository CI evidence

`tests/test_aas_phase9_frozen_parity.py` pins actual AAS scores generated
by executing the attached source using `numpy.random.default_rng(2060)`.
It checks all three statistical algorithms against the current upstream
implementations, for both:

1. `(12,3)` continuous telemetry in **two independent runs** of length 5
   and 7, never treating the second run as continuation of the first.
2. `(3,4,3)` independent windows scored at their **last** timestamp.

The two-sided CUSUM, finite-horizon EWMA and residual PCA-SPE scores are
tested with strict absolute/relative numerical tolerances. In addition,
\`tests/test_aas_phase9_neural_frozen.py\` pins actual AAS USAD/TranAD score
and training-loss vectors generated by setting every tensor parameter to
a deterministic value derived from its canonical upstream state-dict key
(PyTorch 2.10.0 CPU). The neural golden values verify matched-weight
**mathematics**, not equivalence of independent training, real AAS checkpoints
or final threshold decisions. No alarm thresholds are inferred from held-out
samples, and no AAS platform modules are shipped with the tests.

## Direct optional live-source verifier

Use an existing Python environment with NumPy, PyTorch, `torch_like` and
the **trusted user-provided AAS source** available on disk:

```shell
python tools/interop/verify_aas_phase9.py \
    --aas-root /path/to/AAS \
    --report aas_phase9_parity.json
```

The optional tool performs direct AAS/upstream comparisons without
bundling or maintaining copies of the five algorithms. It checks:

- CUSUM, EWMA, PCA-SPE numerical parity on 2-D run segments and 3-D
  independent windows with the declared projection rules.
- USAD and TranAD scores and training loss after transferring **identical
  neural model weights** into upstream architectures with strict key/shape
  validation.
- The AAS USAD decoder keys start `decoder_1.0.weight` and
  `decoder_2.0.weight`; upstream `USAD` wraps them under `.net`,
  e.g. `decoder_1.net.0.weight`. These cannot be loaded directly with
  `strict=True` without an explicit key remapping.
- TranAD modules use matching key prefixes in the inspected source, but
  actual compatibility still requires strict key/shape and numeric checks.
- Run-boundary-aware *causal trailing windows* are constructed by AAS;
  matching upstream scoring on the same windows does not replace that
  application integration obligation.

A positive result is **not** evidence that independent training runs
converge to identical weights. It does not guarantee compatible optimizer
states, full AAS `aas-detector-checkpoint-v1` serialization, calibrated
threshold-state migration, or end-to-end AAS interface parity.

## Next integration gate

Before replacing any copied AAS implementation:

1. Pin an upstream `torch_like` version and verify the runtime environment.
2. Preserve channel naming, sample rate, run identity, normalization, window
   padding, output granularity and threshold ownership.
3. Validate strict USAD decoder key remapping and TranAD keys/shapes with
   genuine AAS-trained checkpoint artifacts on the same CPU/GPU backend.
4. Independently test scores, final labels, threshold state, save/reload and
   Windows deployment in the AAS project.
5. Only then remove the corresponding AAS duplicate source and update its
   license notices and integration documentation.

At present, the upstream algorithm library does not import any AAS
package, database schema or UI code. Production migration of AAS itself
is not included in this PR.
