# IMA literature intake: machine-learning and diagnostics algorithms

Review date: 2026-11-11

Scope: a targeted review of the IMA paper library for methods that could add reusable capabilities to `torch_like`. This is a decision log for the diagnosis, anomaly-detection, RUL, explainability and scientific-ML papers reviewed in this pass; it is not a claim that every document in `ima/paper` has been exhaustively assessed. The goal is capability coverage and implementation quality, not model count.

## Decisions

| Method / paper | Potential contribution | Existing overlap and evidence boundary | Decision |
|---|---|---|---|
| HSNN-IB — *Hierarchical subgraph neural network with information bottleneck for machine remaining useful life prediction*, Information Fusion 127 (2026), DOI 10.1016/j.inffus.2025.103953 | Representative sensor subgraphs, gated cross-subgraph exchange and variational information bottleneck for RUL | Adds a distinct hierarchical sensor-graph RUL mechanism; paper-derived implementation and contract tests are in the full RUL registry. C-MAPSS/SCADA reproduction remains unassessed. | **Implemented**; PR #39 and PR #40 merged |
| ABIGX — *A Unified Framework for Explainable Fault Detection and Classification*, IEEE TPAMI 2026, DOI 10.1109/TPAMI.2026.3689327 | Fault-aware adversarial reconstruction baseline plus Integrated Gradients for detection/classification explanations | Complements the existing diagnosis and fault-source utilities; requires differentiable models. The paper's AFR objective and Eq. (20) use gradient descent, while Algorithm 1 prints the opposite update sign. The implementation follows the minimization objective. | **Implementing**; PR #41 |
| ALDM — *Adaptive Latent Distribution Modeling for Industrial Time Series Anomaly Detection*, IEEE TASE 23 (2026), DOI 10.1109/TASE.2026.3674236 | Sensor-graph attention, temporal contrastive representation learning, adaptive latent metric and conditional flow density | Strong direct fit for unsupervised multivariate anomaly detection. The official MIT repository at https://github.com/YuLiu-61/ALDM has material paper-to-code risks: `TS2Vec.SPD` is instantiated but unused; `timelag_dynamic` constructs a fresh SPD layer and detaches its output, so the advertised adaptive metric is not optimized as a model parameter. The SWaT loader fits scaling before the split, and the training script selects checkpoints using test AUC. | **High-priority candidate, not yet admitted**; requires an independent clean implementation, full-paper/protocol audit and leakage-free benchmark |
| AGIL — *Attention-guided graph isomorphism learning: A multi-task framework for fault diagnosis and remaining useful life prediction*, Reliability Engineering & System Safety (2025), DOI 10.1016/j.ress.2025.111209 | GIN/EdgePool hierarchy with joint fault classification and RUL heads | Uses a fixed handcrafted feature graph (16 feature nodes and Pearson-threshold edges) and a narrow bearing-dataset setup. The library already has GIN, graph/RUL backbones and HSNN-IB; the main gap is a general multi-task diagnosis/RUL contract rather than another GIN encoder. | **Defer** until multi-task training contracts and broader benchmark evidence justify the additional architecture |
| MCCF — *Conformal Fusion Under Missing Modalities*, arXiv:2608.07183 | Modality-dropout fusion, per-modality Dirichlet evidence, Dempster-Shafer fusion and mask-conditional conformal calibration | The current `ModalityConditionedConformalClassifier` already calibrates exact availability-mask groups and refuses unseen masks. MCCF's evidential fusion backbone is additional, but the current source is a preprint and independent validation is not established. | **Observe**; do not duplicate the existing conformal layer or promote the preprint to a mature model |
| SymMatika — *Structure-Aware Symbolic Discovery* | Explicit and implicit symbolic equation discovery | Apache-2.0 C++/CMake implementation at https://github.com/generalroboticslab/SymMatika. `SINDyDetector` already covers a narrower sparse-dynamics discovery/detection path; SymMatika is a broader symbolic-regression capability, not a drop-in detector. | **Future scientific-ML candidate**; first define a Python API and benchmark against SINDy/AI-Feynman |
| AI Feynman — *A physics-inspired method for symbolic regression*, Science Advances 2020, DOI 10.1126/sciadv.aay2631 | Recursive symbolic regression exploiting units, symmetry, separability and compositionality | MIT reference implementation at https://github.com/SJ001/AI-Feynman, but its Fortran extensions and legacy `numpy.distutils` packaging require a compatibility strategy. | **Future scientific-ML candidate**; avoid copying its legacy packaging into the core |
| Universal Differential Equations / Neural ODE and operator-learning papers (FNO, DeepONet, HNN) | Physics-informed dynamics, operator learning and structure-preserving dynamical models | Valuable for scientific computing and aerospace dynamics, but they introduce a distinct operator/physics domain rather than closing a current fault-diagnosis API gap. Existing SINDy is not equivalent to UDE or operator learning. | **Separate future workstream**; define a physics/operator domain before adding models |
| LLM-heavy RUL, federated meta-learning and knowledge-graph diagnosis systems | LLM advice, federated client/server adaptation or retrieval-augmented diagnosis | These are training/deployment systems with external model, data or infrastructure dependencies, not self-contained model architectures. | **Do not add to the core model catalog now**; consider optional integrations only when the corresponding runtime scope exists |
| Zonotope/set-membership and component-specific physical models | Model-based fault detection and physical uncertainty bounds | Useful for aerospace subsystem verification, but they are not generic machine-learning models and should not be disguised as neural algorithms. | **Separate model-based diagnostics workstream** |

## Implementation rules

1. **Do not copy code without an explicit compatible license.** ABIGX is independently implemented from the published equations; its reference repository is not treated as an implementation source. ALDM and SymMatika have explicit MIT and Apache-2.0 repository licenses respectively, but source reuse still requires attribution and a code-level audit.
2. **Paper claims, code claims and local results are separate.** A paper's reported benchmark does not become a `torch_like` result. A passing shape/gradient/API test does not promote maturity or benchmark evidence.
3. **Check split hygiene before reproducing results.** Validation data may select checkpoints; test data must not select epochs, thresholds, scalers, features or hyperparameters.
4. **Prefer distinct capability over architectural duplication.** A new GIN variant is not automatically useful when GIN and multiple graph-RUL models already exist.
5. **Keep system workflows out of the model catalog.** Federated orchestration, LLM agents, knowledge graphs and data governance belong in optional higher-level modules unless a reusable standalone algorithm is isolated.
6. **Keep Stable Wheel scope explicit.** The independent algorithm wheel remains an allowlisted subset; adding a full-framework diagnostics or RUL capability does not silently expand that distribution.
